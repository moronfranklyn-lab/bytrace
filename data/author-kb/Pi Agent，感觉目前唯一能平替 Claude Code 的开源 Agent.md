最近在深度体验一个叫 **Pi Agent** 的开源编程 Agent，感觉可成长性很强。

先说结论，这是我目前用下来，唯一一个能真正平替 Claude Code 的 Agent 架构。开源、不锁模型、MIT 协议，GitHub 7.7 万星。

我算是 vibe coding 的重度用户了，Claude Code、Codex、Cursor 都在用。每个工具我都会认真跑一段时间，不是看个 demo 就下判断。Pi Agent 是我最近这段时间一直在用它推项目的，bug 修复、UI 复刻，基本没太大问题。


## 为什么现在聊这个

6 月底 Claude Code 又一波大规模封号。这次不是普通的风控，是直接被社区扒出来在代码里做了隐形标记。

具体的检测方式挺离谱的。它会读取你本机的时区，如果是 Asia/Shanghai，就把请求里的日期格式从 2026-06-30 悄悄改成 2026/06/30。还会根据你有没有用中转域名，把系统提示词里某个撇号替换成不同的 Unicode 字符，肉眼看起来一模一样，但编码值完全不同。这些信息会被回传到 Anthropic 的服务器，后端直接就能判断你是不是中国用户。

换 IP、换节点、换中转，都没用。因为它检测的不是你的网络环境，是你的设备环境。

国内生成式 AI 的用户已经超过 6 亿了，但真正在用 Claude 这种顶尖模型的人占比非常小。再加上风控越来越严，这些最强的模型大概率不会稳定地留给普通用户用。Anthropic 的政策已经写得很明确了，中国大陆不在它的服务区域内。这不是技术问题，是合规问题。

这件事让我重新想了一个问题，我们不应该把自己的生产资料绑定在任何一个工具上。离了 Claude Code 就写不了代码了？离了某个模型就做不了项目了？那这个能力就不是你的，是平台的。
 
真正该练的是用多个工具的能力。工具是赋能，不是依赖。今天 Claude 好用就用 Claude，明天 Kimi K3 上来了就切 Kimi，后天 DeepSeek 更强了就换 DeepSeek。你的工作流、你的 Skill、你的判断力，这些才是你自己的东西。

所以当我发现 Pi Agent 的时候，第一反应不是"又一个新工具"，而是"这个架构能让我不依赖任何一家"。


## 为什么说 Pi 能平替 Claude Code

先说核心能力。Pi 和 Claude Code 干的是同一件事，都是在终端里跑的 coding agent，都是 read、write、edit、bash 这套基础工具组合。你在 Claude Code 里能做的事，Pi 里基本都能做。我这段时间用 Pi 推项目，bug 修复、UI 复刻都没太大问题。

再说模型。Pi 能接 Claude 的 API，也能接 Kimi、DeepSeek、OpenAI、Google 等 15 个以上的供应商。你用 Claude 的 API 跑 Pi，模型能力本身不打折，但你不再依赖 Claude Code 这个客户端。账号封了，模型还在，换个供应商接上就能继续干活。

最关键的是 Skill 兼容。Pi 装完之后会自动读取 ~/.agents/skills 这个目录。如果你之前在 Claude Code 里搓了一堆 Skill，不用做任何迁移，Pi 直接识别，开箱即用。这不是从零开始，是站在你已有的积累上接着走。

同样的道理，Pi 也支持 **AGENTS.md**。你之前在项目根目录里写好的项目上下文文件，Pi 打开项目的时候会自动加载。你积累下来的那套项目规范、约束、边界，换到 Pi 里一行不用改。


## Pi 的几个特点

**极简**

Claude Code 的系统提示词大概 14000 token，内置 10 多个工具，功能很全但你也改不了它的逻辑。Pi 的系统提示词只有大概 200 token，核心就 4 个工具。

14000 和 200 的差距意味着什么？每一轮对话，系统提示词都会占用上下文窗口。提示词越长，留给你实际工作内容的空间就越少，token 消耗也越大。Pi 把这块压到了极限，把空间尽可能多地留给你的代码和对话。

它的设计哲学很明确，不需要的东西就不装，需要的你自己加。这跟 Claude Code 那种"帮你想好了你需要什么"的思路完全相反。哪种更好取决于你是什么阶段的用户。刚上手 coding agent 的人，Claude Code 的全家桶体验确实更友好。但如果你已经知道自己需要什么、不需要什么，Pi 这种减法设计反而更舒服。

**开源透明**

MIT 协议，你能看到每一行代码在干什么。这在 Claude Code 封号事件之后变得格外重要。Claude Code 能在代码里偷偷植入检测逻辑，是因为它是闭源的，你看不到它在做什么。Pi 不存在这个问题，所有代码都摆在 GitHub 上，社区在盯着。

出了 bug 你可以自己修，想加功能你可以自己写扩展，不用等官方排期。这种掌控感在用了一段时间之后会越来越明显。

**扩展生态**

Pi 默认不带 MCP、不带子 Agent、不带权限弹窗、不带 plan mode，但这些全都可以通过扩展装上去。官方提供了 50 多个扩展示例，覆盖面很广。

几个值得关注的扩展：

- **pi-web-access**，给 Pi 加上网页搜索和内容抓取能力
- **pi-codex-goal**，长任务的目标追踪，防止 Agent 跑偏
- **pi-vision-proxy**，通过其他模型给 Pi 加上图片分析能力
- **pi-cursor-sdk**，如果你有 Cursor 的订阅，可以直接在 Pi 里调用

扩展通过 `pi install npm:包名` 安装，跟装 npm 包一样简单。你可以按自己的需求一个一个加，也可以一个都不装，就用最干净的 4 工具版本。


## 三个 coding agent 的体感差异

用了这么多 coding agent，我自己有一个判断框架。

**Claude Code 适合从 0 到 1。** 你给它一个模糊的想法，它能帮你把整个项目结构搭出来，像一个能跟你一起想问题的伙伴。它会主动帮你考虑文件结构、技术选型、边界情况。但到了 1 到 n 的微调阶段就比较痛苦，它有时候改 1 处动全身，你让它改个按钮颜色，它顺手把旁边的布局也重构了。你越想精确控制它，它越喜欢自由发挥。

**Codex 适合从 1 到 n。** 指哪打哪，执行力很强，特别适合精细微调。你说改这个文件的第 30 行，它就改第 30 行，不会碰别的地方。但它对提示词要求高，你得说得非常清楚它才能执行好。让它从 0 搭一个中大型项目基本搭不起来，它需要你把任务拆得足够细，一个一个喂给它。更像一个合格的助手，不是搭档。

**Pi 适合已经有一套自己工作流的人。** Claude Code 和 Codex 你都得按它的规矩来，Pi 是你自己定规矩。而且因为它不锁模型，你可以在不同任务上用不同的模型。需要强推理的时候切 Claude，需要长上下文的时候切 Kimi K3，日常轻量任务用 DeepSeek 省成本。这种灵活性是绑定单一模型的工具给不了的。

所以这三个工具不是谁替代谁的关系，更像一条路径。Claude Code 帮你起步，Codex 帮你执行，Pi 让你按自己的方式干活。


## 安装和上手

Pi 的安装只需要一行命令。打开终端，粘贴这行：

```bash
curl -fsSL https://pi.dev/install.sh | sh
```

等它跑完就行了。

![[pi-install-complete.png]]

安装完成后第一次启动，它会自动补充一些缺失的依赖，这个过程比较无感，下载也很快。

![[pi-first-launch.png]]

打开之后是一个非常极简的 CLI 界面。页面上显示 Pi 的版本号，以及默认安装的一些 Skill，搜索、文档、表格、PPT 这些基础功能都有。

![[pi-cli-interface.png]]

配置模型，终端里输入 /login，选你要用的模型供应商，填 API key 就行。支持 Anthropic、OpenAI、Kimi、DeepSeek、Google 等 15 个以上的供应商。

装好之后几个常用操作：

- **/model** 切换模型，也可以用 Ctrl+L 快速打开模型选择器
- **Ctrl+P** 在已配置的模型之间快速轮换
- **Shift+Tab** 调整思考深度
- **/compact** 对话太长的时候压缩历史消息，释放上下文空间
- **Enter** 在 Agent 执行过程中发送干预消息，可以随时纠正方向
- **Alt+Enter** 排队发送后续消息，不打断当前执行

如果你之前用 Claude Code 或者其他编程工具已经把 Skill 装在 ~/.agents/skills 目录下了，Pi 会自动识别，不用做任何迁移。


工具会来来去去，平台会封会改会倒闭。但你搓过的 Skill、你跑通的工作流、你对 AI 能做什么不能做什么的判断，这些东西是跟着你走的。

Pi Agent 吸引我的不是它功能多强，是它把选择权留给了我。不绑定任何一家，随时能切，随时能走。

与其花时间研究怎么防封号，不如花时间让自己不怕封号。
