## 使用时机

完成中心主张和最小论证后读取本文件。需要起草全文、改结构、改成小普口吻、审查自然度或选择文章形态时也读取。

默认同时读取 `corpus-index.md`，只选择与当前任务相关的二到四个写作动作。不要为了模仿风格而常驻加载全部标优文章。

## 文章任务是路由，不是模具

先看这篇文章需要替读者完成什么任务，再决定证据、下钻方向与终审重点。文章任务可以组合，但不能因此套用固定章节。

| 文章任务 | 读者主要问题 | 证据与收益重心 |
|---|---|---|
| 热点或发布解读 | 发生了什么，为什么值得关心 | 最新事实、矛盾、机制与一个有边界的判断 |
| 技术科普 | 它是什么，怎样影响真实任务 | 准确定义、任务场景、类比、工作机制和使用边界 |
| 产品或案例拆解 | 为什么这样设计，对谁有效 | 实测、用户任务、信息架构、竞品与业务机制 |
| 推荐与选型 | 值不值得用，和谁相比，适合谁 | 真实测试、竞品、成本、失败、适用与不适用对象 |
| 实测与复盘 | 实际发生了什么，怎样复现或避坑 | 版本、任务、过程、截图、结果、失败与修复 |
| 方法论或 SOP | 读者怎样完成一件事并验证结果 | 步骤、案例、模板、提示词、验收标准与边界 |
| 职业与个人叙事 | 一次选择怎样形成，经验怎样迁移 | 真实时间线、关键材料、条件、代价与迁移方法 |

允许混合任务。例如发布解读可以继续下钻到商业机制、推荐选型和验证方法。不要用“出现了几个栏目”判断是否跑题；用以下条件判断一次扩展是否应该保留：

1. 它由上一部分自然产生，仍在回答同一条读者问题链。
2. 它新增了证据、理解、选择、行动、验证能力或可复用材料。
3. 它有事实、案例或明确推导支撑。

三项满足就继续写。删除重复和无证据内容，不因为篇幅变长删除真正收益。字数是结果，不是目标。

多个扩展同时满足时，按对核心读者的边际收益排序，优先保留最能改变理解、判断、行动或验证方式的部分。下一层不再产生这种变化，或只是在重复证明已经成立的结论时停止；其余内容改成旁注、资料附录或另文，不让“都有关”变成无限扩张。

需要结构化方法时，只设置一个主框架，最多再设置一个辅助框架；不需要时不强造框架。其余“维度、边界、步骤、指标”并入主框架、改成普通解释或证据表，不连续包装成多套方法论。

计数时看认知功能，不看排版名称。可以被独立命名和复用的维度模型、决策矩阵、路由树、多步方法或评测体系都各算一个框架，即使写成表格或流程图；原始证据表、测试结果表、时间线、操作记录和来源清单不计。辅助框架必须服务主框架的同一个读者决策。

Standard 和 Deep 在定大纲时先写内部预算：

```yaml
framework_budget:
  main:
  auxiliary:
  absorbed_content: []
```

出现第三套可复用结构时，把它并入主框架或辅助框架，改成不独立命名、不另起编号体系的解释、证据或验证动作。不能把“五步法”改叫“执行清单”后继续作为第三套方法。

文章任务只提供写作重心，不能替代 `insight-argument.md` 中的论证图和读者问题链。推荐、选型与实测还必须读取 `recommendation-testing.md`。

## 同心圆读者与进入文章的楼梯

核心读者决定文章最终能写多深，相邻读者决定有多少人愿意继续看。开头可以宽，结论可以深；不要为了照顾非专业读者降低专业密度，要用共同利益和逐层解释为他们搭一段楼梯。

起草前确认：

- 核心读者最后需要获得怎样的专业判断。
- 相邻读者最先能感知的任务、成本、风险或好奇心是什么。
- 两者共同关心的利益是什么。
- 哪些术语、Benchmark、价格和参数需要先转成可感知的任务后果。

正文搭桥时优先使用真实材料：

- 先说明一个技术概念会改变哪项任务，再解释概念本身。
- 先说明某个 Benchmark 模拟什么能力，再展示分数。
- 把价格换成一次任务、一个工作流或一次成功交付的成本，不只报每百万 Token 单价。
- 跨越技术、产品或商业层级前，补上读者接受下一步判断所需的最小前提。
- 可以从真实实测、反常事实、价格账或使用场景进入，不强制虚构人物和贯穿全文的故事。

终审时分别以核心读者和相邻读者通读：前者是否觉得不够深，后者会在哪个概念或转场失去理解与兴趣。

## 选择揭示顺序

根据论证依赖选择顺序，不套“现象、原因、三点建议、升华”骨架。

常用顺序包括：

- **实验过程**：预期、尝试、失败、根因、调整、结果、方法。
- **问题到机制**：反常事实、常见解释、证据冲突、真正机制、影响。
- **旧流程到新变化**：旧基线、变化点、被替代与未被替代的部分、适用边界。
- **个人经历到可迁移方法**：事件链、关键选择、证据材料、抽象规则、使用条件。
- **任务拆解**：读者任务、必要步骤、示例、常见错误、验收方式。
- **对照推理**：同一任务下的多个方案、逐项证据、排除过程、结论。

标准和深度文章至少在内部比较两种可能顺序。选择能最早建立可信度、最少重复背景、最自然处理反方的一种，不必把两个方案都展示给小普。

优先让每个主要部分回答 `reader_question_chain` 中的一个问题，并自然产生下一层问题。问题链是理解顺序，不必在正文里写成连续反问。

小标题由信息密度和导航需要决定。教程、报告和长方法文通常需要；短评和强叙事可以不用。只有选择会显著改变阅读体验时才让小普单独拍板。

## 三遍式起草

标准和深度文章默认分三种认知任务完成，不要求保存三份全文。已有成熟草稿时只补最弱的一遍，不机械重写。

### Pass A：事实与论证稿

- 为每一部分写清 `claim / evidence / mechanism / boundary / reader takeaway`。
- 允许语言朴素，先保证事实和因果关系成立。
- 明确背景段、证明段和作者判断，不让案例漂浮。
- 保留所有待确认标记，不用流畅句子掩盖缺口。
- 完成后检查最强反方和证据边界。

Fast 模式的 Pass A 可以只是六行主张图。已有完整草稿时，直接修补最弱的事实或论证部分，不必重写全文。

### Pass B：读者引导与内容下钻稿

- 用共同利益让相邻读者进入，再按问题链逐步走向核心读者需要的深度。
- 检查每个主要部分是否增加新的理解、选择、行动、验证能力或可复用材料。
- 在专业术语、Benchmark、参数、价格和抽象框架前补足最小理解前提。
- 中心主张成立后，不急着收尾；继续检查读者是否还缺选择方法、行动材料或验证方式。
- 允许事件、技术、商业和方法论环环相扣地继续下钻，但删除脱离同一读者问题的横向发散。
- 控制结构化框架数量；需要时一个主框架、最多一个辅助框架，不需要时不强造。
- 对照 `framework_budget`，把额外的维度、步骤和评测流程吸收到两套预算内。

Pass B 不能用虚构人物、对白或场景换取代入感。需要真实实测或个人经历时，退回证据账本或 `recommendation-testing.md` 补材料。

### Pass C：小普声音稿

- 在不新增事实、不扩大结论的前提下，重排信息、选择场景并调整节奏。
- 让第一人称承担亲历、判断或责任，不只承担气氛。
- 用具体产品名、动作、失败和结果替代抽象形容。
- 保留真实不确定性，不用“可能、大概、也许”逃避本可明确的判断。
- 删除重复解释、报幕式过渡和段尾升华。

Pass C 想加入新的对话、情绪、动作或结果时，退回证据账本确认，不能自行补足。

## 第一人称与作者在场

AI 可以作为小普的发布叙述者直接写“我”，包括在开头使用第一人称。共创是判断、材料和编辑权的分工，不是强制保持第三人称。

作者在场有三种有效方式：

1. **亲历在场**，写真实做过什么、遇到什么、怎么判断和结果如何。
2. **判断在场**，对公开事实提出有边界的独立解释。
3. **选择在场**，说明为什么采用某个方法、放弃什么，以及代价是什么。

不要用虚构情绪、对白或动作制造“活人感”。没有第一手经历的分析文可以少用“我”，不能硬塞身份声明。

## 小普的正向写作动作

优先学习标优文章中反复有效的动作，而不是统计词频：

- **快速建立可信接近性**：开头不一定讲自己，但应尽早说明事实来自亲测、后台、项目材料或可回查来源。
- **先给真实矛盾，再给概念**：让读者先看到哪里不对劲，再命名它。
- **把失败写完整**：写预期、现象、根因、修复和新规则，不只写“踩坑”。
- **给数据补口径**：主动说明样本、端别、活动流量、时间窗口或统计限制。
- **事实后立即给判断**：先摆材料，再用一两句说明小普看到的机制，不绕长过渡。
- **用对照挣得结论**：比较同一任务的不同做法，让选型和判断从证据中出现。
- **从个人经验交付可迁移物**：把经历整理成检查表、模板、框架、决策条件或可执行步骤。
- **回到核心矛盾收尾**：结尾回应开头的问题或意象，不再另起宏大议题。

正向动作按题材选择，不要求每篇全部使用。幽默来自真实细节和自然反应，不靠随机网络热词。

## 标题、开头与结尾

### 标题

- 给出明确对象和阅读承诺，最好包含真实张力、反差或新判断。
- 标题力度不能超过正文证据。个人体验不要包装成永久行业定论。
- 数字、时间和“唯一、彻底、全部”等词都要能被正文兑现。
- 同时给出信息型和张力型候选时，说明各自适用平台，不堆同义标题。

### 开头

从最有证明力的入口开始，可以是第一人称经历、具体事实、数据、对话、产品结果或行业反常。不要强制第三人称，也不要强制情绪开场。

开头应尽快完成两件事：建立可信接近性，提出全文要解释的矛盾。删除“今天想聊”“本文将”“你是不是也有这种感觉”等通用暖场。

### 结尾

优先选择回到核心矛盾、交付行动、说明边界或保留小普态度。不要重新总结全文，不要突然引入新议题，不要为了有余韵而上升成时代宣言。

## 时间、年份与版本的自然表达

研究层和表达层使用不同精度。先根据文章发布日期建立时间参照，再把内部记录转换成正常人会说的话。

小普、来源或测试日志给出的精确信息默认是事实材料，不是要求逐字保留的正文措辞。只要转换后没有改变事件先后、测试对象和比较关系，省去完整年份、日期或构建号不算丢失事实。

### 内部证据层

在来源、简报、测试卡、文件 frontmatter 和图片元数据中保留：

- 完整日期，如 `2026-08-01`。
- 精确模型或产品版本、构建号、仓库 release 或 commit。
- 测试环境、平台、价格口径和访问时间。

这些信息用于核验和复现，不等于要原样进入每一段正文。

### 正文表达层

- 文章发布当年通常写“今年”“最近”“这次”；需要和其他年份并列时写“26年”，不习惯性写“2026年”。
- 上一年通常写“去年”；只有多年份对照或离开发布日期后会产生歧义时，才写“25年”。
- 更早年份优先写“24年”“23年”。完整四位年份只在历史精度、引用名称、正式政策或跨世纪歧义确实重要时使用。
- 同一时间信息不要反复出现。标题、开头或事实段已经建立参照后，后文使用“这次、当时、后来、现在”。
- 日期优先写“今天、这周、上个月、8月初”。精确到某一天只有在发布时间差、版本先后、价格生效或事件顺序会改变判断时才需要。
- 产品和模型在正文中使用读者熟悉的短名。完整小版本、构建号或 commit 只在复现测试需要时，在测试说明、图注、脚注或资料卡中出现一次，后文改用短名。
- 普通文章开头默认不出现四位年份、完整年月日、构建号或 commit。先让读者知道这件事为什么值得关心，再把必要精度放进测试说明、图注、脚注或资料卡。
- 把相邻日期合并成自然关系。例如同日写“今天”，前一天写“发布前一天”，不要在两句话里连续报两个完整日期。
- 把年份比较改成读者当下会说的话。例如文章发布于 26 年时，`2025年的模型` 通常写成“去年的模型”。

如果文章会脱离发布日期单独传播，先判断“今年、去年”是否仍能被 frontmatter 或平台日期锚定；无法锚定时使用“26年、25年”，仍不必升级成报告式的完整日期。

只有小普明确要求技术记录、复现报告、版本变更说明，或精确时间与版本本身决定结论时，正文才提高精度。即使如此，也只在第一次承担证明时写全，不反复播报。

## 语言与节奏

- 使用大白话表达判断，专业术语在真实工作语境中自然出现。
- 根据意义分段。移动端通常适合短段，但不要把普通句子机械切碎。
- 短句用于停顿、反转和强调，不设置数量配额。
- 保留有逻辑作用的转折，删除“下面来看”“思路就是这样”等报幕。
- 一条判断可以在标题、正文和结尾以不同信息层级重现，但不要原句复读或连续划重点。
- 真实的不确定性必须写清范围；没有证据的强断言不能冒充“有立场”。
- “其实”“说实话”“确实”“你看”等口语词只在自然需要时出现，不主动播种。
- 括号吐槽、粗口和感叹只服从真实语境。严肃主题或没有真实情绪时不要加入。

以下表达默认重写，除非出现在准确引语中：

`让我们一起`、`在当今时代`、`不可否认`、`综上所述`、`值得注意的是`、`不难发现`、`说白了`、`这意味着`、`本质上`、`换句话说`

避免把破折号、箭头、引号和“标签：解释”式冒号当成批量制造节奏的工具。准确引用、自然语法和技术表达不需要为了机械过检而改坏。

## 去除 AI 痕迹

完成 Pass C 后执行一次删改：

1. 删掉预告下一段、复述上一段和提醒读者“重点来了”的句子。
2. 删除事实后面第二次出现的同义判断，尤其是段尾升华。
3. 把“非常重要、巨大变化、深刻影响”等形容词换成可观察事实，或直接删除。
4. 删除“我突然意识到”“我愣住了”等未经确认的戏剧连接。
5. 检查每个案例是否改变论证；只负责装饰的案例删掉。
6. 检查比喻数量。一个比喻已解释清楚时，不继续叠秘书、医院、楼层等多个体系。
7. 找出“换一个懂 AI/产品的人也能写”的段落，补小普真实判断或证据；补不了就压缩。
8. 保留不完全光滑但自然的表达，不把错别字、病句和标点混乱当成人味。

## 成文门槛

进入生产与发布前确认：

- 结构由论证需要决定，没有强套内容形态模板。
- 第一人称事实均能回到证据账本。
- Pass B 已经为相邻读者搭桥，并让主要部分各自增加新的读者收益。
- Pass C 没有新增未经确认的事实和情绪。
- 标题承诺与正文证据匹配。
- 正文时间、年份和版本说法自然，内部证据精度没有丢失。
- 如使用结构化框架，全文最多一个主框架和一个辅助框架。
- 关键判断只在需要的层级出现，没有连续重复和强行升华。
- 文章既有可读性，也保留明确机制、边界和读者带走物。

随后读取 `quality-production.md` 规划图片、文件状态、语义终审和发布。
