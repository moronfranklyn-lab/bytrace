## 使用时机

在以下任一情况读取本文件：

- 小普还没有明确选题，希望一起找题。
- 只有一个宽泛话题，需要确定为什么现在值得写。
- 已有资料，需要区分事实、亲历、推断和假设。
- 文章含时效性信息、外部数字、产品能力、职业建议或第一人称经历。

如果只是修改一句话、标题或已定稿段落，不要为了完整流程强行读取本文件。

## 从当前输入开始

先判断材料成熟度，不要让小普重复提供已经说过的信息。

| 当前输入 | 处理方式 |
|---|---|
| 没有题目 | 进入选题发现 |
| 有话题、没角度 | 建立读者契约，再生成候选角度 |
| 有资料、没判断 | 整理证据账本，交给洞察层寻找张力 |
| 有明确判断 | 核验判断所需证据，不重新选题 |
| 有大纲或草稿 | 只补它缺少的证据和身份信息 |
| 只需改写局部 | 保留原意和事实边界，直接处理 |

## 选题发现

只有在小普需要选题时才执行。把原来的独立选题能力作为本技能的条件分支，不要求先调用另一个 Skill。

1. 收集近期事实、产品变化、行业争议、小普最近的实操和读者问题。
2. 区分热点本身和可持续的问题。热点回答发生了什么，文章要回答为什么、对谁有影响、下一步怎么判断。
3. 优先寻找小普有真实接近性的题目，包括亲自使用、负责过相似业务、掌握后台数据、经历过失败或形成过方法。
4. 为每个候选题形成一张紧凑选题卡，不先写标题党文案。
5. 最多给出少量真正不同的候选角度，并说明取舍。不要用十个近义标题冒充十个选题。

选题卡至少包含：

```yaml
topic:
trigger:
why_now:
reader:
reader_problem:
common_view:
possible_xiaopu_angle:
author_proximity:
available_evidence:
missing_evidence:
factual_risk: low | medium | high
possible_visuals: []
```

用好奇心、信息量和共鸣感检查候选题，但不要机械打分。一个题目只要有清晰读者价值和足够材料，也可以不追热点。

## 实时选题雷达

小普说“最近有什么可以写”“扫一下热点”或要求从信息源找题时，按当前日期重新抓取，不用记忆里的旧热点冒充实时结果。

默认检查六个来源：

| 来源 | 主要用途 | 使用边界与抓取提示 |
|---|---|---|
| `aibase.com/zh/news` | 国内 AI 事件与数据线索 | 当事实线索，不照抄措辞；关键事实继续回查原始来源 |
| `woshipm.com/news`、`woshipm.com/ai` | 国内产品圈热度信号 | 首页可能只显示局部内容；只用来判断讨论热度，不搬同平台作者的角度和结构 |
| `sspai.com` | 科技工具与尝鲜热度 | 只用标题和传播信号判断是否发酵，不搬文章论证和案例 |
| `simonwillison.net` | 工程师第一手模型与 Agent 实践 | 优先提取可回查的实验、版本和工程细节 |
| `jack-clark.net` | AI 研究与政策周刊 | 适合发现国内尚少见的研究问题，继续回查论文或原始公告 |
| `latent.space/archive` | Agent、评测和工具取舍访谈 | 根首页可能依赖脚本渲染，优先检查 archive；访谈观点与事实分开记录 |

`bensbites.com/archive` 可以作为补充源，不作为默认必抓。来源长期失效时如实说明，不静默换源并假装完成了全量扫描。

### 扫描步骤

1. 从每个可用来源提取近期条目、日期、事实摘要、具体数据和原始链接。
2. 标注抓取质量。只有局部首页、无法确认日期或二手转述时，明确写出限制。
3. 将同一事件和相近问题跨源聚类，不把六份列表直接交给小普。
4. 将跨两个独立来源、或单源但有强数据和一手材料的话题标为强信号。
5. 将单源、数据薄弱但与小普真实经验高度相关的话题标为探索信号。
6. 过滤纯八卦、纯行情、无数据也无转化价值的噪音。宁可候选少，不凑数。

### 版权与原创边界

- `woshipm` 和 `sspai` 上的成型文章只提供热度信号，不能把同平台作者的角度、论证顺序、案例和表达改写成小普选题。
- 聚合资讯只提供事实线索。关键数字、产品发布和公司说法尽量回到官方公告、原始数据或直接报道。
- 海外博客和访谈可以提供国内稀缺的一手线索，但仍要区分受访者观点、记者概括和可核实事实。
- 候选角度必须重新从小普的经验、读者问题和证据张力中形成，不能把“翻译海外文章”当作原创洞察。

### 从热点转成文章

热点只是钩子。每条候选都要说明读者最终能带走什么，优先寻找：

- 一套判断框架或决策条件。
- 一套可以复用的流程或 SOP。
- 小普愿意做或已经做过的真实测试。
- 一组具体踩坑与绕过方式。
- 一个被公开讨论忽略、但能由证据解释的机制。

涉及测试、复现和项目经历时，把它作为提案询问小普是否做过或愿不愿意做，不能把建议动作写成已经发生。

候选清单在对话中输出，除非小普明确要求保存。每条至少包含：

```yaml
topic:
hotspot_hook:
cross_sources: []
data_or_first_hand_signal:
source_quality:
reader_payoff:
proposed_xiaopu_action:
possible_angle:
author_proximity_question:
suggested_platform:
factual_risk:
```

按写作潜力而不是纯热度排序。小普选定后继续在同一个 `xiaopu-writing` 中建立读者契约、证据账本和 Insight Brief，不再交接到另一个写作 Skill。

## 读者契约

写大纲前先建立同心圆读者契约。核心读者决定文章最终深度，相邻读者决定文章能否让更多正常人进入；不要把目标读者理解成排除其他人。

```yaml
core_reader:
adjacent_reader:
shared_stake:
prior_belief:
desired_shift:
why_now:
author_proximity:
assumed_knowledge:
concepts_to_bridge: []
payoff_ladder:
  understand:
  decide:
  act:
  verify:
```

- `prior_belief` 记录读者现在可能相信什么或卡在哪里。
- `desired_shift` 只写一个主要变化，可以是新判断、新选择或新动作。
- `shared_stake` 找到核心读者和相邻读者都在意的利益、风险或选择，用它作为进入文章的桥。
- `assumed_knowledge` 和 `concepts_to_bridge` 决定哪些术语可以直接使用，哪些需要先用任务、结果或类比解释。
- `author_proximity` 说明小普为什么接近这个问题，不要只写泛化身份标签。
- `payoff_ladder` 说明读者能获得怎样的理解、选择、行动和验证能力。不是每篇都要四项齐全：热点短评可以停在理解和判断；推荐、方法论和实测文章必须继续交付行动、边界或验证方式。

如果这些信息能从小普已有材料中可靠推断，直接形成工作假设并标明；只有会改变文章方向时才询问。

## 研究与来源

研究的任务是支持或推翻主张，不是把搜索结果堆进正文。

1. 对可能变化的信息重新核验，包括产品功能、版本、价格、人物职位、市场数据、法规和招聘趋势。
2. 技术与产品事实优先使用官方文档、产品公告、原始数据和论文；行业判断可以补充高质量二手分析。
3. 在内部材料中保存来源标题、链接、完整发布日期、访问日期、精确产品版本、统计口径和它支持的具体主张。正文如何自然表达时间与版本，交给 `composition-voice.md`，不要把证据账本的格式直接复制进文章。
4. 区分“来源说了什么”和“小普如何解释它”。不要把推断伪装成原文结论。
5. 遇到相互冲突的数据时，呈现口径差异或缩小结论，不挑一个最刺激的数字。
6. 找不到可靠来源时，删除精确数字、降低结论强度或保留待确认标记。不要用模糊措辞掩盖未核实事实。

## 证据和身份账本

为标准和深度文章建立账本。短内容可以压缩成几行，但仍要区分证据类型。

| 类型 | 含义 | 可直接写入正文吗 |
|---|---|---|
| `first_hand_confirmed` | 小普本轮明确提供的动作、结果、判断或原话 | 可以，在原事实边界内组织 |
| `historical_first_hand` | 已发表文章或旧材料中的小普经历 | 可以，标明时间，不扩写缺失细节 |
| `external_sourced` | 有可回查来源的外部事实 | 可以，关键主张保留来源 |
| `inference` | 从证据推导出的解释或判断 | 可以，但明确是判断并控制强度 |
| `explanatory` | 为帮助理解而设的案例或类比 | 可以，但不能承担事实证明 |
| `hypothetical` | 假设场景、待测试方案或 AI 候选 | 只能明确写成假设，不能伪装成亲历 |

推荐字段：

```yaml
- statement:
  type:
  source:
  date:
  supports_claim:
  status: confirmed | needs_source | needs_xiaopu
  limits:
```

第一人称权限遵守以下边界：

- 可以把已确认的动作、过程和结果写成自然的“我”。
- 可以复用公开文章里的历史经历，但不能自动改成现在仍然如此。
- AI 提出的观点候选在小普确认前，不能写成“我一直认为”或“我后来意识到”。
- 情绪、对白、动机、现场动作、感官细节和因果连接，只有小普明确提供时才能写。
- 不用“作为一个 AI 产品经理”替代真实接近性。第一人称应承担证据或判断责任。

核心原则：可以让真实经历更清楚，不能让缺失经历更完整。

## 补充小普材料

不要逐条审问。先完成能完成的研究，再一次性提出最能提高文章上限的问题。

优先询问：

1. 哪个关键判断必须由小普拍板。
2. 哪个真实动作、失败细节或结果能区分这篇文章和普通综述。
3. 哪个情绪或对白准备以第一人称发布。
4. 哪条证据缺失会迫使核心结论降级。

问题应具体到能直接补入账本，例如“你实际测试的是哪个版本，失败发生在哪一步”，不要问“还有什么想补充的吗”。

## 进入洞察层的门槛

满足以下条件后读取 `insight-argument.md`：

- 已明确主要读者变化，或能形成合理工作假设。
- 已区分核心读者与相邻读者，知道正文需要为哪些概念搭桥。
- 已至少明确收益阶梯中的一个主要交付；推荐、实测和方法论文章还要有行动、边界或验证层。
- 已知道小普与问题的真实接近性，没有接近性时也已明确采用外部证据路径。
- 核心事实已分类，时效性事实有核验计划。
- 个人经历中的待确认内容没有被当成既成事实。
- 材料足以生成至少两个候选解释，而不是只有一个预设结论。

若门槛未满足，说明缺口并选择补证、缩题或改成探索性文章，不要直接进入文风润色。
