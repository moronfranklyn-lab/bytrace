## 使用边界

本文件只管理文章视觉，不决定文章事实、洞察和声音。先完成 `quality-production.md` 的正文终审，再进入本文件的实际生图阶段。

硬边界：

- 草稿、改稿和事实补证阶段只允许规划视觉清单、写占位符和准备素材。
- 正文没有得到小普明确的“定稿”“正文没问题”或同义确认时，禁止调用任何图像生成工具。
- 不用“先试一张”“先做个封面”绕过正文定稿。
- 最终封面和内文生成图默认由 Codex 的内置图像生成能力完成；在其他环境运行到这一步时只交接最终正文、视觉清单和参考资产，不擅自换用别的生成器。
- 实际生图前必须读取当前可用的 `imagegen` Skill 并遵守其调用、参考图、检查和落盘规则。
- 图像不能补写正文没有的事实，不能把示意画面冒充产品截图、测试结果或现场记录。

小普临时只要求分析图片机会、改提示词或审图时，完成当前任务即可，不强制推进整套流程。

## 视觉生产状态机

`文章简报.md` 只维护一条 `visual_status` 摘要，逐图状态全部写入 `配图交接.md`：

```yaml
visual_status: planned | pilot_review | batch_authorized | evidence_waiting | assets_ready
visual_production:
  locked_title:
  locked_draft_sha256:
  ip_reference:
  pilot_cover_id:
  pilot_internal_id:
  remaining_approved_at:
```

```text
planned
  -> 正文 locked，分别生成封面和第一张内文图
pilot_review
  -> 小普确认 Pilot 并明确授权剩余批次
batch_authorized
  -> 完成其余生成图；若真实证据尚缺
evidence_waiting
  -> 所有已采用任务 ready 或 declined、文件写回且发布视觉检查通过
assets_ready
```

若文章没有真实证据任务，完成批次后可以从 `batch_authorized` 直接进入 `assets_ready`。`assets_ready` 只表示视觉资产完成，不表示测试证据或整篇文章已经可以发布。

正文锁定时记录最终标题和正文文件 SHA-256。若生图后又修改标题、中心判断、章节顺序、图片对应段落或关键数据：

1. 对比修改前后内容。
2. 把受影响图片退回 `needs_review`；标题变化必然使封面失效。
3. 重新获得正文定稿确认后，只重做受影响图片。

纯标点、错字和不改变画面含义的局部修正可以保留成图，但要复核标题和图中文字。

在 Pilot 开始前和剩余图片批次开始前，都要重新读取 `canonical_body_path` 指向的正文并重算 SHA-256，与 `locked_draft_sha256` 比较。`草稿.md` 只在简报明确登记为正文或符号链接别名时使用。只在初次锁定时记录一次不够；任何一次不一致都先停止生图，判断修改是否影响画面，再重新锁定或复核受影响图片。

## 最终正文与视觉清单

图片只从最终正文推导。不要用早期大纲、过期对话稿或旧版视觉清单生图。`配图交接.md` 是逐图视觉任务的唯一权威清单；`文章简报.md` 只保存锁定正文、总体状态和数量摘要。

视觉清单至少包含一张封面和一张内文解释图。其余数量由信息价值决定，不按字数配额，也不为了均匀间隔填图。

优先选择认知锚点：

- 文章的中心矛盾或核心判断。
- 读者第一次需要理解的关键机制。
- 单靠文字难以比较的关系、流程或取舍。
- 真实测试产生的关键结果。
- 高密度段落中真正能降低理解成本的视觉。

先在 `配图交接.md` 记录一份同篇共享的风格契约。Pilot 反馈后原地更新，不在简报里再维护一份自由文本风格说明：

```yaml
style_contract:
  mode: hand_drawn_editorial | custom
  style_reference:
  style_reference_sha256:
  background:
  line:
  label_language:
  accent_colors: []
  density:
  vertical_balance:
  ip_policy:
  forbidden: []
```

每张图记录：

```yaml
- id:
  role: cover | internal | evidence
  source_section:
  text_anchor:
  function: explain | prove | relieve
  visual_mode: generated | real_screenshot | source_figure | composite
  supports_claim:
  one_sentence_visual:
  required_elements: []
  forbidden_elements: []
  ip_role:
  ip_decision_reason:
  style_reference:
  style_reference_sha256:
  input_assets:
    - path:
      sha256:
      role: identity | style | edit_target | evidence
  source_material: []
  privacy_or_copyright:
  status: proposed | accepted | waiting_source | generating | style_review | needs_review | ready | replaced | declined
  output_path:
  pixel_size:
  file_sha256:
  known_limitations: []
  qa_waivers: []
  approval_event:
  prompt_used:
```

`one_sentence_visual` 必须能用一句话说清画面。说不清通常意味着一张图塞了多个观点，应拆分或删除。

`ip_role` 允许为 `none`。内文图先完成信息构图，再判断人物是否能承担不可替代的观察、操作、指向或叙事作用；删除人物不损失理解时就使用 `none`。

`accepted` 只表示小普决定采用；真实截图、日志或来源图尚未提供时立即改为 `waiting_source`。`ready` 必须同时具备可读文件、实际像素、文件 SHA-256 和质检结论；小普接受一个已知瑕疵时，把问题写进 `known_limitations`，把原话、日期和影响写进 `qa_waivers`，不得假装问题不存在。

## 小普 IP 参考资产

小普上传并确认的人物图是身份垫图，不是可被随意改造的普通素材。默认资产固定为相对当前 Skill 根目录的 `assets/ip/xiaopu-ip-reference.png`。

生成规则：

- 封面必须使用小普确认的 IP 图。内文图只有在视觉清单的 `ip_role` 不是 `none` 时才引用，不为统一露出强行加人。
- `ip_role: none` 是逐图最高优先级约束，覆盖旧配图 Skill、通用模板或提示词中“必须出现小普/Agent/人物”的默认要求；改由物件、路径和动作承担叙事。
- 决定加入 IP 前先问：人物是否真正解释了动作、关系或叙事？能否自然占据现有构图节点？如果答案是否定的，就删除人物，而不是缩小后塞进空白处。
- 采用 IP 时在提示词里明确：参考图只负责人物身份、脸部特征、发型和基本气质；文章正文负责场景与构图。不要照抄参考图背景和版式。
- 保持面部辨识度、发型、年龄感和核心服装气质稳定，不把人物换成“相似的亚洲男性”。
- 默认保留黑色系服装；确需换装时先说明画面理由，不改变人物身份。
- 采用 IP 时必须有动作或认知角色，例如观察、指向、操作或验证；不能只贴成角落水印，也不能悬空插在二元对立、流程或矩阵的空白处。
- 封面必须出现 IP，但不做最大主体。内文图可以完全没有人物；需要人物时，以本段信息关系为主，同时保证缩略图中人物仍清楚可辨。

资产调用：

- 先以当前 `SKILL.md` 所在目录为根，解析 `assets/ip/xiaopu-ip-reference.png` 的绝对路径；不要依赖当前工作目录猜路径。
- 封面和 `ip_role` 不是 `none` 的内文图，实际生图前检查固定资产并用图像查看工具确认内容，再把本地文件作为身份参考；`ip_role: none` 的图片不要传人物参考图。
- 需要 IP 时始终优先使用固定资产，不再依赖最近对话图片，因此连续生成多张时不会丢失身份锚点。
- 需要 IP 而固定资产缺失、损坏或内容不符时停止该图生图。只有小普在当前对话重新提供了正确原图时，才可临时使用能够包含它的最小最近图片数量，并应先修复固定资产。
- 需要 IP 时不同时传本地参考路径和最近对话图片，不能用旧成图、搜索结果或文字描述冒充身份垫图。
- 该文件是小普个人身份资产，只允许随个人备份源和个人 Codex 安装副本同步。公开分享、上传仓库或把 Skill 发给第三方前，必须先移除 `assets/ip/` 并清理身份引用。

## 封面规则

默认画幅为 16:9；平台另有明确尺寸时按平台覆盖。先为平台缩略预览设计，再考虑大图细节。

### 构图

- 默认左标题、右主视觉。
- 左侧约 52% 至 58% 是标题构图区，但所有标题文字严格落在画面左侧 48% 的半幅裁切安全区，中线附近保留呼吸空间。
- 右侧约 42% 至 48% 放文章专属主视觉和小比例 IP。
- 即使平台只截取左半幅，读者仍应看见完整标题和清楚的主题线索。
- IP 的视觉面积可参考全画面的 8% 至 15%，通常不超过右侧主视觉的三分之一；百分比只提示视觉关系，不做像素级验收，最终以辨识清楚但不抢标题为准。

### 标题

- 标题是第一视觉层，使用小普最终确认的标题原文，不擅自改词、加副标题或制造第二个标题。
- 可做自然换行，但不能拆坏词组和语义重音。
- 中文字必须逐字正确。存在错字、漏字、重复字或笔画不可辨时，封面不合格。
- 不默认添加日期、作者、平台口号、来源和小号说明。

### 主视觉

- 主视觉表达本篇中心判断或矛盾，而不只是复述文章对象。
- “模型、AI、工具”不能自动等于芯片、机器人头、发光大脑或随机代码雨。
- 优先使用一个可在缩略图中认出的对象、动作或对比关系。
- 画面不塞正文摘要，不把封面做成信息海报。

## 内文图规则

内文图默认 16:9，保持同篇一致。每张只解决一个认知任务。

- 缩到约 480 像素宽时，仍能一眼看出主体、关系和结论方向。
- 使用一个主动作或一种关系；元素通常控制在三组以内。
- 能不用字就不用字。必须用字时优先 0 至 3 个短标签，字号足够大，不写小段正文。
- 图中的信息顺序与上下文一致，不让读者重新猜阅读方向。
- 先在没有人物的情况下完成信息关系。只有人物能明显提升理解、叙事或品牌识别，并能自然嵌入关系节点时才加入；否则设为 `ip_role: none`。
- 二元对立、左右比较、对称矩阵和已经闭合的流程图，默认不在中间或空白处插入 IP。人物不是用来填空或打破对称的装饰。
- 采用 IP 时不设机械面积配额：它既不能压过信息主体，也不能小到缩略图中只剩一个突兀人影。以动作可读、身份可辨、构图自然为验收标准。
- 留出足够空白，避免密集卡片、连续小图标、装饰线和无意义背景纹理。
- 留白必须服务分组、阅读和呼吸，不以大面积空白营造所谓高级感。让主体组在画布中垂直居中，顶部和底部只保留必要安全边距；不得因内容整体上移造成底部空旷，也不得同时出现大块无效的上下留白。缩略预览时，有效内容应稳定占据主要画幅而不贴边。
- 同一篇的线条、色彩、人物比例和标签样式保持一致，但不机械重复同一构图。

旧配图 Skill 中的多 Agent 结构只在文章确实讨论协作、分工或工作流时按需使用。不要为了“有场景”强塞角色；普通解释图优先只保留必要对象，IP 是否出现由信息作用和构图决定。

## 推荐与实测文章的证据图

生成型插画负责解释，不负责证明真实测试。

- 产品界面、输出结果、日志、代码、成本记录和对比结果优先使用真实截图或真实文件。
- 不能让图像模型生成一个“看起来像真实产品”的界面来支撑“我测了”。
- 真实证据区不得经过生成式重绘。默认直接使用原图或小普确认过的脱敏版本；需要统一视觉时，只能用确定性排版把截图完整放进有明确边界的外框，让小普 IP 位于证据区外侧。不能把截图送进图像生成模型后再当作原始证据，也不能改动、遮挡或重绘关键结果。
- 涉及账号、密钥、个人信息和未公开项目时先脱敏。脱敏不能改变支持结论的关键数据。
- 证据图的原始文件、裁剪版和最终版保持可追溯关系，在交接清单写明来源。

## 默认视觉语言

在小普没有指定新方向时，沿用个人 IP 的默认文章视觉：

- 白色或轻微暖白背景。
- 黑色手绘线条为主，边缘清楚，整体克制。
- 只用少量橙红、红或蓝做信息强调，不铺满高饱和色。
- 大留白、少元素、高对比，避免写实摄影背景和复杂 3D 质感。
- 画面像编辑插图或简洁知识图，不像企业咨询报告、儿童贴纸或模板化科技海报。
- 线条应有清爽但轻微抖动的手绘笔触，不是精准矢量描边。默认不用整排粉彩填充圆角卡、渐变、投影和光泽来区分节点。
- 遇到流程、路线、分流和系统关系时，先把抽象关系物理化为传送带、分流扳手、闸门、水管、抽屉、秤或其他当前内容专属的低科技动作隐喻；不要直接落成正式流程图，也不要机械复用同一个物件。
- `ip_role: none` 时，让物件、路径和动作承担叙事，不用彩色卡片墙代替被移除的人物。
- 同一篇只建立一套视觉语法；封面可以更有冲击，内文图保持更干净。

默认只是 Pilot 的起点。小普对封面和第一张内文图的反馈会成为本篇最终风格说明。

## Pilot 生成与风格确认

正文锁定后，按正文阅读顺序选择第一张 `accepted` 的生成型内文解释图。不要用真实截图充当风格样张；若阅读顺序第一张不足以代表既定视觉方向，在展示时说明局限，而不是悄悄改选后面的图。

Pilot 阶段只做两张：

1. 封面。
2. 第一张已采用的生成型内文图。

两张图片分别调用一次图像生成，分别质检。完成后同时展示给小普，并先给出自己的具体判断：

- 标题层级和半幅裁切是否安全。
- 主视觉是否真的表达文章判断。
- 若使用 IP，相似度、动作、可辨识度和构图角色是否合适；若不使用，关系是否因此更直接。
- 内文图缩小后是否仍读得懂。
- 线条、留白和强调色是否需要统一调整。

然后邀请小普给出微调意见。问题要落在可以直接修改的维度上，不只问“好不好看”。

若需要修改，优先一次只改变一个主变量，例如 IP 变小、标题上移、减少标签或更换主隐喻。修改后重新检查，不把多个未验证方向混在一次重做中。

“封面可以”只代表封面可标记为 `ready`。第一张内文图仍保持 `style_review`，应具体询问它是否可用或需要改哪里；没有内文 Pilot 的明确确认，不能自行修改它，也不能开始剩余图片。

若小普在看完两张 Pilot 后直接说“按当前风格一次生成剩余图片”或同义表达，视为同时确认当前内文 Pilot 风格并授权剩余批次，不再重复询问。

## 剩余图片生产

Pilot 达到可用状态后，必须明确询问：是否按当前风格一次生成其余已采用配图。

- 没有得到明确答复，不开始剩余图片。
- 小普同意后，把所有 `accepted` 的剩余生成图作为一个生产阶段完成，中途不逐张请求风格确认。
- “一次生成”指一次授权、连续完成和统一交付，不代表把多张不同图片塞进一次图像生成调用。
- 每张不同图片仍单独调用一次图像生成，使用同一份本篇风格说明；只有 `ip_role` 不是 `none` 的图片使用 IP 参考图。
- 其余生成图优先把已确认的内文 Pilot 作为 `style reference only` 传入，并明确只继承背景、线条、笔触、强调色和标签语言，不复刻构图。`ip_role: none` 的任务优先选用不含人物的已确认 Pilot；若只有含人物样张，则用文字锁定风格并继续明确禁止人物。
- 某张失败时只修该张，不让其他已合格图片随之漂移。

## 图像生成调用

实际调用前完整读取 `imagegen` Skill。关键执行约束：

1. 先查看本地参考图和任何待编辑图片。
2. 封面和 `ip_role` 不是 `none` 的生成图必须使用固定 IP 参考资产，并清楚标注它只承担身份锚定；`ip_role: none` 的内文图不传人物参考图。需要人物而固定资产不可用时停止该图生图。
3. 本地参考图与最近对话图片二选一，不能同时使用。
4. 每个不同的视觉任务使用一次独立调用。
5. 生成后查看原图，不只相信返回提示。
6. 项目成图从系统生成目录复制到当前文章的 `imgs/`，不能只留在临时目录。
7. 在 `配图交接.md` 记录最终提示词、参考资产、生成结果和修复历史。
8. 参考资产和风格样张都记录路径与 SHA-256；只写文件名不算可追溯。

## 质检与修复

每张图至少检查五层，并同时查看原始尺寸与约 480 像素宽的缩略预览；不要只看生成器返回的小图。用文件实际尺寸填写 `pixel_size`，不能从提示词推断。

### 1. 内容

- 是否支持视觉清单中的唯一主张。
- 是否新增正文没有的数字、界面、因果或结论。
- 真实证据是否保持原样且来源清楚。

### 2. 文字

- 封面标题是否逐字正确。
- 标签是否完整、自然、足够大。
- 是否出现乱码、伪汉字、多余英文或模型自动补出的说明。

### 3. IP

- `ip_role: none` 时，画面是否没有意外人物，信息关系是否比加入人物更清楚。
- 采用 IP 时，人物是否仍是小普，而不是相似路人；发型、年龄感、面部和服装气质是否稳定。
- 采用 IP 时，人物是否承担明确动作或认知角色，在缩略图中可辨，同时没有破坏信息构图。

### 4. 构图

- 封面左侧标题能否独立成立，半幅截取是否安全。
- 内文图缩略到约 480 像素宽后是否仍能识别。
- 是否只有一个视觉中心，是否有足够留白。
- 主体组是否垂直居中；顶部、底部是否出现大块无效留白；视觉中心是否因某一侧过空而明显漂移。
- 默认文章手绘风是否误生成成正式流程图、PPT 信息图、粉彩圆角卡片墙或精致扁平商业插画；出现任一项即退回重做，而不是只调颜色。

### 5. 同篇一致性

- 背景、线条、强调色、人物比例和标签语言是否一致。
- 一致性来自视觉语法，不来自每张图复制相同姿势和布局。

发现问题时先分类并写一句可验证的修复目标：

- 文字、局部布局、身份相似度或单个对象错误，使用定向编辑，只改变被点名变量。
- 视觉模式、中心隐喻或整体构图方向错误，从零重生成；失败图不能继续充当后续图片的风格参考。
- 小普明确接受某个不影响主张的已知瑕疵，可以保留成图，但必须登记 `known_limitations` 与 `qa_waivers`，并把修正规则应用到后续图片。

## 文件、命名与写回

文章工作区结构扩展为：

```text
文章/临时工作区/<article-id>/
├── 文章简报.md
├── 草稿.md
├── 配图交接.md
└── imgs/
    ├── <article-id>-cover.png
    ├── <article-id>-fig-01-<short-name>.png
    └── <article-id>-fig-02-<short-name>.png
```

- `article-id` 使用全库唯一且适合文件名的稳定标识，建议为 `YYYYMMDD-short-slug`。文件名按正文顺序编号，不把完整提示词或临时版本号写进文件名，也不让不同文章都叫 `cover.png`。
- 修复中的中间图放系统生成目录或明确的临时子目录；只有通过质检的版本进入 `imgs/`。
- 替换图片前检查目标是否存在，不静默覆盖小普手工修改过的文件。
- 正式发布前，把通过质检的图片安全复制到 `/Users/ahai/Library/Mobile Documents/com~apple~CloudDocs/Documents/XIAOPU/文章/插图/`，保留全库唯一文件名。确认目标不存在或确实是本次受控替换后，再使用 `![[<article-id>-fig-01-<short-name>.png]]` 等引用替换占位符；拒绝的建议从发布稿删除。
- 写回后重新运行文章发布 lint 和工作区发布检查，并逐个检查正式图片引用对应的文件实际存在；再复读正文和 `配图交接.md`，确认顺序、文件名、链接与图片状态一致。
- 每项最终只能收敛为 `ready`、`waiting_source` 或 `declined`。只要还有 `accepted`、生成中或待审项，状态就不完整；只要还有 `waiting_source`，`visual_status` 就是 `evidence_waiting`，不能设为 `assets_ready`。
- 只有全部已采用任务均为 `ready`、已落盘并写回正文，或经小普明确拒绝后设为 `declined`，`visual_status` 才能设为 `assets_ready`。

## 异常处理

- **正文未定稿**：继续完善正文或视觉清单，不生图。
- **标题未确认**：不生成封面。
- **固定 IP 参考图不可用**：封面或当前 `ip_role` 需要人物时停止生图并修复 `assets/ip/xiaopu-ip-reference.png`；无法恢复时请小普重新上传原图，不近似重建。`ip_role: none` 的内文图不受影响。
- **只有截图没有生成型内文图**：为文章选择一张真正承担解释作用的生成图作为 Pilot；截图仍按证据素材处理。
- **封面中文错误**：不接受带错字版本，针对标题区域修复或重做。
- **小普只批准封面、没有评价内文图**：把封面标为 `ready`，内文图保持 `style_review` 并具体询问是否可用或需要改哪里；不自行修改，也不生成其余图片。
- **小普改变视觉方向**：更新 `style_contract`，只重做受影响图片，不默认推倒正文。
- **视觉模式根本错误**：从零重生成，不把失败的正式流程图、PPT 卡片图或错误隐喻继续作为风格垫图。
- **小普接受已知瑕疵**：将图设为 `ready`，同时登记 `known_limitations` 和 `qa_waivers`；后续图片执行修正规则，不反复要求修改已接受成图。
- **真实证据尚缺**：任务设为 `waiting_source`，总体设为 `evidence_waiting`；生成型解释图可以完成，但不得把总体状态写成 `assets_ready`。
- **正文在成图后发生实质修改**：对比正文，退回受影响图片并重新获得定稿确认。
- **只剩会话附件、需要连续生成多张**：先把小普确认的原图恢复到固定资产路径；不能让参考图滑出最近图片窗口后继续生成。
- **平台尺寸改变**：从已确认视觉语言适配新尺寸，重新检查标题安全区和裁切，不直接拉伸旧图。
