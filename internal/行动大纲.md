## 1. 现状盘点（已实地核查，非猜测）

### 1.1 应用是什么

本地跑的 Next.js 15 Web 应用，数据存本机 SQLite。核心链路：

| 链路 | 入口 | 干什么 |
| --- | --- | --- |
| 风格指纹 | `/fingerprints` | 粘 3–5 篇博主文章 → 拆成 12 维度 + v3.3 结构能力（`structure_repertoire` / `depth_pattern` / `analogy_bank`） |
| 站点画像 | `/sites` | 给板块 URL → 爬最近文章 → 板块级 + 编辑级画像 |
| 写作 | `/compose` | 一段思路 + 指纹 + 站点画像 → 大纲 → 正文（可多平台一次出 N 版）→ AI 改写 diff |
| 深度调研 | `/research` | 选题 → codex 联网搜集 → claude 起草 → codex 审查 → ≤2 轮回炉 |
| 素材库 | `/compose` Step 7 | 本地配图扫描 / 打标 / 按风格自动配图 |
| 风格配方 | `/recipes` | 跨博主碎片组合，命名保存复用 |
| 选题 | `/topics` | 真实爬取文章 → TF-IDF → 模型合并出题 |
| 历史文章 | `/articles` | 按文章分组，平台 chip 切换版本，看 AI 改写差异 |

### 1.2 技术栈锁定（已在跑，不换）

`Next 15.5.18` / `React 19.2.6` / `TypeScript 5.9.3 strict` / `better-sqlite3 11.10.0` (WAL) / `Tailwind 3.4` (CSS 变量三主题) / `Zustand 5` / `nanoid 5`

### 1.3 必须写进文档的现存问题（这是「补齐文档」的最大价值）

| 编号 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P1 | `lib/claude.ts` 里**硬编码了你的机器路径** | `FALLBACK_CLAUDE_CANDIDATES = ['/Users/mixingtumima0000/.local/bin/claude', ...]` | 换电脑必挂，客户端化必须清 |
| P2 | `lib/db.ts` 用 `process.cwd()` 定位数据库 | `resolveDbPath() = join(process.cwd(), 'data', ...)` | 双击启动器一旦换工作目录，DB 就找不到 |
| P3 | 环境变量名**三套并存** | `.env.local.example` 写 `AUTOARTICLE_LLM_*`，代码里还读 `OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODEL`，文档又提 `CLAUDE_BIN` | 你填 .env 时不知道填哪个才对 |
| P4 | 无「主 Agent / 联网搜索」两组独立配置 | 现在全靠 `AUTOARTICLE_LLM_PROVIDER` 一个开关切整个应用 | 没法做到「写作走 A 家、搜索走 B 家」 |
| P5 | 无健康检查 / 无配置向导 | 没有 `/api/health`，缺 key 时报错散落各处 | 客户端化后你无法一眼看出「哪儿没配」 |
| P6 | 品牌名分散 | 4 处页脚、3 处导航、`layout.tsx` metadata、`lib/claude.ts` 系统提示词、`lib/prompts/xiaopu-writing.ts` | 改名字要一次改干净 |
| P7 | `xiaopu` 命名残留 | 代码文件 7 处引用 + 2 个 `data/xiaopu-*` 目录名 | 见方案一「小普清理范围」（范围已收敛） |

## 2. 四个方案（按你要求一个一个来，每个做完向你汇报再进下一个）

### 方案一 · 补齐项目文档

**产出物**（全部新建在 `autoarticle/docs/`，不覆盖你现有的 AGENTS.md / CLAUDE.md / STATUS-*.md）：

```
docs/
├── 行动大纲.md              ← 本文件
├── PRD.md                   ← 产品需求文档（8 字段模板，参照开发助手的 PRD 模板）
├── ARCHITECTURE.md          ← 架构文档（七层架构，参照 agent-blueprint 的 BLUEPRINT.md）
├── API.md                   ← 全部 32 个 API route 的请求/响应/错误/SSE 事件表
├── DATA-MODEL.md            ← SQLite 全部表 + 列的字典（含 schema-additions-*.sql 的 10 个补充文件）
├── TECH-STACK.md            ← 技术栈与选型理由（为什么 Next 而不是 Electron、为什么 better-sqlite3）
├── ENV.md                   ← 环境变量总表（方案二改造后回填）
├── DEPLOY.md                ← 本机安装 / 启动 / 排错 / 数据备份
└── 项目状态.md               ← 进度 + 决策台账（沿用开发助手的模板）
```

**做法**：
1. 逐个读 `app/api/**/route.ts`（32 个）提取真实入参/出参/SSE 事件名，**不靠猜**。
2. 逐个读 `lib/schema*.sql` + `lib/db.ts` 的 `ensure*` 建表函数，生成完整数据字典。
3. 读 `lib/prompts/*` 归纳「主 Agent 到底被喂了什么系统提示词」——这部分写进架构文档的「认知层」。
4. 按 agent-blueprint 的七层架构映射：
   `L1 交互层`(app/*/page.tsx) → `L2 编排层`(compose/research 状态机) → `L3 模型层`(lib/claude.ts) → `L4 工具层`(crawler / images / search) → `L5 数据层`(SQLite) → `L6 约束层`(AGENTS.md 铁律 + 反爬边界) → `L7 交付层`(export / 启动器)

**「小普」清理的范围（Ethan 已明确：风格 / 博主指纹不算）**：

| 层 | 在哪 | 是什么 | 怎么处理 |
| --- | --- | --- | --- |
| ① 工具名 | 页脚 4 处、导航 3 处、`layout.tsx` metadata、`lib/claude.ts` 系统提示词 | 产品叫 AutoArticle | 改成 **ByTrace / 笔迹** |
| ② 代码层标识 | `lib/prompts/xiaopu-writing.ts`（文件名 + import 到 article/outline/critic） | 只是模块名 | 文件改名 `xiaopu-writing.ts` → `writing-rules.ts`，同步改 3 处 import。**导出的常量名 `XIAOPU_*` → `WRITING_*`** |
| ③ 方法论资产目录 | `data/xiaopu-skill/`（SKILL.md + 8 个 references md） | 你的写作方法论原文 | 目录改名 `xiaopu-skill` → `author-skill`，**md 内文一个字不改**，同步改引用路径 |

**明确不动**：
- ❌ prompt 里「你是小普的作者型共创伙伴」「不能编造小普没提供的经历」这类**作者人设表述**——保持原样
- ❌ 博主风格指纹相关的一切命名（`fingerprints` / 博主名 / 风格标签）——不算品牌名，不动
- ❌ `data/xiaopu-article-kb/` 你自己文章知识库的**内容**——不动（目录名是否跟着改，见 §4 Q1）
- ❌ 任何已生成的文章正文、指纹数据、素材

**验收方式**：我把 `docs/` 目录树 + PRD 全文贴给你，你打开 markdown 看内容对不对。改名部分我跑一遍 grep 证明没有遗漏，并列给你每一处改动的前后对照。

### 方案二 · API 改 .env（主 Agent + 联网搜索 + 深度调研）

**目标**：你把 API 链接和 key 填进一个 `.env`，任意一组都能独立换供应商；不填就自动降级回本机 CLI（保证你现在能跑的状态不被破坏）。

**新的 .env 结构（草案，待你补充供应商）**：

```bash
# ============ 1. 主 Agent（大纲 / 正文 / 指纹拆解 / 审稿 / 改写）============
BYTRACE_AGENT_PROVIDER=        # anthropic | openai | deepseek | kimi | glm | minimax | claude-cli | codex-cli
BYTRACE_AGENT_BASE_URL=        # 例：https://api.deepseek.com/v1
BYTRACE_AGENT_API_KEY=         # 你的 key
BYTRACE_AGENT_MODEL=           # 分析类模型（指纹/大纲/审稿）
BYTRACE_AGENT_ARTICLE_MODEL=   # 正文类模型（降 AI 味）

# ============ 2. 联网事实搜索（compose 的「事实底座」+ gather）============
BYTRACE_SEARCH_PROVIDER=       # tavily | google-cse | mimo | duckduckgo | ...
BYTRACE_SEARCH_API_KEY=
BYTRACE_SEARCH_BASE_URL=
BYTRACE_SEARCH_MAX_RESULTS=5

# ============ 3. 深度调研（/research 的搜集 + 审查）============
BYTRACE_RESEARCH_PROVIDER=     # 可复用 1 或 2 的配置，也可独立
BYTRACE_RESEARCH_API_KEY=
BYTRACE_RESEARCH_BASE_URL=
BYTRACE_RESEARCH_MODEL=

# ============ 4. 本机 CLI 兜底（不填 API 时用）============
BYTRACE_CLAUDE_BIN=
BYTRACE_CODEX_BIN=
BYTRACE_CODEX_CWD=
```

**做法**：
1. 先做 **兼容层**：`lib/env.ts` 统一读新变量，旧变量（`AUTOARTICLE_*` / `OPENAI_*`）继续兜底 —— 保证你填新的时候旧的还能跑，不会中途瘫痪。
2. 改造 `lib/claude.ts` 的 `resolveApiConfig()` / `normalizeProvider()` 支持新分组。
3. 改造 `lib/search/*` 支持搜索组独立配置。
4. 改造 `lib/research.ts` 支持调研组独立配置。
5. 清掉 P1 硬编码路径、P3 三套变量名并存。
6. 生成 `.env.example`（带注释说明每个 key 去哪申请）+ `.env.local` 实际模板。
7. **不碰**配图 API、不碰爬虫。

**验收方式**：我给你一份「填 4 行就能跑」的清单；你填完我跑真实冒烟（出一篇真实文章），把过程录给你。

**需要你提供**：你到底想接哪几家？（比如「主 Agent 用 DeepSeek、搜索用 Tavily」）你不定我就按兼容主流 6 家来预留。

### 方案三 · 本机客户端化（可双击安装 + 启动）

**目标**：装一次，之后双击图标就用，不用开终端、不用记 npm 命令。

**产出物**：
```
install.command          ← 双击＝自动装依赖 + 建配置 + 装桌面图标
笔迹 ByTrace.app          ← 伪装成 app 的启动器（AppleScript/Dock 可固定）
scripts/doctor.ts        ← 环境自检：Node / CLI / key / DB / 端口 逐项体检
app/api/health/route.ts  ← 新增健康检查端点
~/Library/Application Support/ByTrace/   ← 数据搬到标准位置（解决 P2）
```

**做法**：
1. **数据搬家**：`lib/db.ts` 的 `process.cwd()` 改成「优先读 `BYTRACE_DATA_DIR`，没配则回退当前行为」，数据默认落 `~/Library/Application Support/ByTrace/`。**先做备份再迁移，迁移脚本可回滚。**
2. **启动器**：检测端口（不用 3100 固定值，冲突自动 +1）、检测依赖、起服务、就绪后自动开浏览器。
3. **桌面图标**：生成 `.app` 包（内含启动 shell），可拖进 Dock / 应用程序。
4. **首次运行向导**：没有 `.env.local` 就自动从 `.env.example` 生成，页面顶部提示「还没配主 Agent key，点这里」。
5. **`doctor` 自检**：一条命令告诉你哪项没配、哪个 CLI 没装、DB 在不在。
6. 加 `BYTRACE_PORT` 可选端口。

**验收方式**：我录一段「从零双击 → 浏览器打开 → 写出一篇文章」的完整步骤给你，你自己照着点一遍。
